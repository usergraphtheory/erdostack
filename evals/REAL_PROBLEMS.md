# Real problems behind the cases

The repositories the eval cases run in are generated: this project may only use public or generated data, and
the sandbox the evals were built in has no network, so no real user's repository or production data is in
here. What a case can be is a faithful staging of a problem that really happens. This file is the register of
those problems. A case that reproduces one names it in its `case.yaml` (`sources: [RP-03]`), and
`evals/PROVENANCE.md` reports how much of each skill's evidence rests on registered problems.

Rules, following the repo's sourcing rule (ideas are free to use, wording is not):

- An entry states the problem in our own words and points at where it is documented. Nothing is copied from a
  source: no text, example, schema or data.
- **Status** says how strong the entry is. `read` means the page's own text was read on the date given (in a
  search excerpt; whole pages could not be opened where the register was written). `executed` means the behaviour was reproduced on
  this machine. `bundled` means a real public dataset that ships with an installed library. `repo` means the
  fact is already in a skill's `SOURCES.md` with its own status. `memory` means stated from prior knowledge of
  the documentation and not re-read: treat it as unverified.
- An entry can also record when the alarming-looking thing is **fine**. Those are the source of restraint
  cases, where the right review says "leave it".

## What is not in this register

Problems that only exist in a private system, anything from an employer's code or data, and any text, example
or dataset taken from a book, paper, vendor guide, forum answer or third-party repository. Forum threads are
cited above only as evidence that a problem occurs; nothing in a case is taken from them.
